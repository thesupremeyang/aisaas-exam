# 2026-11-02 浏览器级并发彩排（L4）

> 目的：用**真实 Chrome**跑真实页面，补上协议级压测看不到的那一层（JS、WS、渲染、页面交互）。
> 结论：**15 个真实浏览器并发 100% 成功、0 JS 报错、0 HTTP 错误、各阶段 p95 < 3s**；
> 45 个浏览器没能跑完，但**瓶颈是压测机（8 核 8G，load 27.9），不是服务器（load 0.06、0 个 4xx/5xx）**。

---

## 一、怎么搭的

| 项 | 值 |
|---|---|
| 压测机 | MacBook，**8 核 / 8 GB**，走公网访问 |
| 被测 | `http://117.72.185.237:18080/web/`（4 核 / 15 GB） |
| 驱动 | Playwright + 系统 Chrome（headless），每个考生一个独立浏览器上下文（独立 cookie/localStorage） |
| 数据 | 临时测试场次 + 4 道题 + 45 个考生账号 + 45 条报名（跑完已全部删除，含 38 条草稿作品） |
| 每个考生做的事 | 打开考试页 → 登录 → 进考场 → 打开作品编辑器（新标签页）→ 保存草稿 |
| 脚本 | `scripts/loadtest/browser45.mjs` |

## 三、这组数字说明什么

### 已经证明的

1. **真实浏览器里能跑通**：登录、进考场、加载题目、打开作品编辑器，全流程无 JS 报错、无失败请求。
2. **应用交互很快**：15 并发下，登录 2.8s、门户 2.4s、编辑器 2.2s（p95），全是真实 Chrome 渲染 + 真实接口。
3. **WebSocket 正常**：15/15 建立连接；45 那轮服务端记录到 **98 次 101 升级**，没有一次失败。
4. **服务器没到瓶颈**：45 个浏览器同时打，服务器 load 0.06、零 4xx/5xx。

### 没有证明的

**"45 台机器同时开考"这一秒。** 本机 8 核 8G 只能带动 15 个左右的真实浏览器上下文，
再往上是我这台机器先撑不住（load 28、按钮点不动），不是服务器。

这不是服务器的问题，但也不能说"45 台已验证"——**这一层必须在同区域的一台压测机上跑，或者进机房彩排**。

---

## 四、要真验 45 个浏览器，三种做法

| 方案 | 成本 | 真实性 |
|---|---|---|
| **A. 同区域云压测机**（8C16G，装 Chrome + 本脚本，`--n=45`） | 一台按小时计费的 VM | 高（内网带宽，接近机房） |
| **B. 三台机器 × 15 上下文** | 3 台普通电脑 | 高 |
| **C. 机房彩排 45 人** | 一次组织成本 | 最高（金标准） |

脚本已经参数化，`--n=45 --wave=45` 直接可跑；换机器只需改 `--base` 和 `--chrome`。

---

## 五、顺带验证到的两件事

1. **考试页首屏资源偏重**：主包 1.65 MB，45 个浏览器同时冷启动时，公网下载要 30–45 秒。
   机房内网会快很多，但如果考场带宽一般，建议开考前让考生提前打开页面（或做一次预热）。
2. **草稿态表单是只读/隐藏的**：作品编辑器在草稿状态下身份核验字段不可编辑，
   所以本轮只压到"打开编辑器 + 保存草稿"，没有覆盖"填表 → 交卷"这一段；
   交卷路径仍以接口级验证为准（含重复答卷唯一键、超时收卷）。

## 六、复现

```bash
# 压测机准备
npm i playwright-core
node scripts/loadtest/browser45.mjs --n=15 --wave=15 \
  --base=http://117.72.185.237:18080/web/ \
  --chrome="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
```

退出码：0 = 成功率 ≥ 99%；1 = 未达标。
